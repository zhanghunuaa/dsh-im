# Fork notes (site build)

This fork of [xmanrui/dsh-im](https://github.com/xmanrui/dsh-im) is based on **v5.2.0** and carries
site-specific changes maintained on the `site/ready-go-5.2.0` branch:

1. **Ready/go continuous input (WeCom direct chats)** — send `ready`, then text/images/files, then
   `go` to submit them as one turn. The first `ready` also performs `/new` (clears the session
   binding) so each batch starts in a fresh DSH session.
2. **Merged-forward guidance** — WeCom AI-bot callbacks carry only the `merged_msg` type, so the
   bot answers with an actionable workaround instead of a generic unsupported message.
3. **Resilient media downloads** — collected attachments are retried, re-checked before `go`, and
   a failed attachment is omitted with a notice instead of failing the whole batch.
4. **No IM sidebar entry** — the client plugin no longer registers `sidebar.panellist`. The panel
   stays reachable from the plugin detail page (`打开 IM机器人`) and the DSH settings page.
5. **WeCom video in and out** — inbound `msgtype=video` frames are AES-decrypted through the SDK
   downloader and staged as a workspace file (`[视频]` label), including inside `ready`/`go`
   batches; outbound `.mp4`/`.mov`/`.m4v`/`.webm`/`.avi`/`.mkv` artifacts prefer a native video
   message (title = file name) and fall back to a file attachment when the provider rejects it.

## Install from this fork

```json
"@xmanrui/dsh-im": "github:zhanghunuaa/dsh-im#v5.2.0-custom.3"
```

`lib/client.js` is committed, while `lib/index.js` is generated by the `prepare` script
(`node plugin-src/client/build.mjs && node plugin-src/host/build.mjs`). Package managers must be
allowed to run that script:

* npm runs `prepare` for git dependencies automatically.
* pnpm blocks it until the resolved dependency is listed in `allowBuilds`
  (`pnpm-workspace.yaml`); the error message prints the exact key, for example
  `'@xmanrui/dsh-im@git+https://github.com/zhanghunuaa/dsh-im.git#<commit>': true`.

Text files are checked out with LF line endings (`.gitattributes`).

## Tests

`npm test` passes the WeCom, i18n and client-plugin-page suites; a few unrelated tests fail on
current Windows/Node environments (feishu workspace-title rendering, image-input size and
update-service timing) — they fail the same way on the pristine v5.2.0 tag. The video work adds
coverage in `test/channels/wecom/bridge.test.mjs` and `test/artifact-delivery.test.mjs`.

## Updating from upstream

Merge the next upstream tag, re-apply the four changes above, then bump the tag. The `prepare`
script documents the exact build commands.
